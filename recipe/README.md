# FS2 install-time recipe

This directory is the human-readable source for the FARLAND SAGA II localisation.
The patcher does not ship a prebuilt archive of patched game resources. It reads
the user's pristine `FarlandSaga2.bin`, `FarlandSaga2.exe` and `Texture.tex`,
applies this recipe, verifies every generated byte, and writes the changed
sectors and files itself.

Nothing here contains game bytes. The inputs are text, label boxes, colour
indices, font roles, operation lists, an executable patch offset, and expected
SHA-256 hashes.

## Layout

- `manifest.json` — recipe version, languages, disc identity, executable and
  texture recipes, and the resource index (archive offset, size, original hash).
- `resources/<id>.json` — one recipe per generated resource. A tile atlas lists
  erase regions, label boxes and styles; a 1bpp text bank lists slot writes; a
  description bitmap holds one wrapped paragraph; an opening character card
  stores its tile geometry, palette indices and translated layout; a script
  resource lists the big-endian u16 words to repoint; a nameplate stores its
  canvas, line bands and translated name.
- `story.json` — story-page layout, language fonts and timing constants.
- `story_pages.json` — the story page index: page id, bank, archive offset,
  size and the original SHA-256 of every 4096-byte page.
- `exe.json` — the executable patch: original and patched hashes and sizes, and
  the exact offset and byte pairs to replace.
- `texture.json` — the `Texture.tex` atlas: original identity, dimensions and
  part count; the box of every changed menu part; seven option panels; and the
  translated labels with their font role and fitting limits for each language.
- `fonts.json` — public font roles: `NotoSansSC` (zh-CN), `Galmuri11` (ko-KR),
  `LiberationSans` (en-US), their atlas-specific subsets, and `Unifont` for the
  title-menu, place-name and story bitmap glyphs.
- `render` on a label selects its mask renderer. `pillow` rasterises the
  language font and `unifont` uses Unifont's bitmap glyphs. The value is either
  one name or a per-language map such as `{"en-US": "unifont"}`. The English
  battle menus use proportional Unifont at 8px: Liberation Sans breaks up at
  that size after the 1-bit threshold, while Unifont stays crisp and fits the
  atlas tile budget.
- `fonts/` — the committed OFL font subsets and their licence texts. The
  subsets contain the characters used by the committed recipes and the story
  text.
- `expected/<language>.json` — the required patched SHA-256 of every disc
  resource. A recipe edit that changes pixels must update these hashes; the
  installer refuses to write a resource whose generated hash does not match.
- `plan.lock.json` — the length and SHA-256 of the rendered plan blob. The
  compiler refuses to emit a plan with different bytes, so a font, layout, or
  rasteriser change cannot reach a release by accident.

## Compiling the plan

```sh
./uv.sh run --locked python tools/compile_recipe.py
```

The compiler rasterises text with Pillow, packs 1bpp slots, emits one mask per
label, renders the three texture languages, and writes
`patcher/plan/plan.bin`. Every font load pins `ImageFont.Layout.BASIC`: when
libraqm is installed, Pillow otherwise switches to Raqm/HarfBuzz, which changes
shaping and bytes for some strings. The expected reference bytes use the basic
layout, so the pin keeps every machine on the same renderer.

The compiler then compares the blob length and SHA-256 with `plan.lock.json`.
A mismatch is a hard error, and the message names the identity fields that
moved. When a recipe edit intentionally changes rendered bytes, review the
plan and rerun with `--write-plan-lock` to accept the new blob. Pass
`--report <path>` for an optional JSON build report; keep it outside
`patcher/plan/`, which the Go build embeds whole. The compiler never reads the
game, so a clean checkout produces the same rendered blob byte for byte. The
gzip wrapper can differ with the host zlib, so the lock covers the uncompressed
blob rather than the plan file. `go build -tags saga2` embeds the plan;
`patcher/plan/plan.bin` is ignored by git.

Texture label and panel layers are stored as raw RGBA in the blob. Pillow's PNG
encoder uses the host zlib, which changed the plan bytes between Fedora and the
Ubuntu CI runner even when the decoded pixels matched. Raw rows keep the blob
independent of zlib, and the plan's gzip wrapper still compresses the mostly
transparent layers.

The plan starts with `FS2RECIPE1\n`, a little-endian u32 header length, a
compact JSON header, and a gzip blob. The JSON header declares plan format 2;
the installer rejects other formats. The blob holds the mask and image layers;
the header holds offsets, boxes, file identities and the executable patch. The
release build carries only this plan — there is no ZIP fallback for the sequel.

CI compiles the plan before `go vet`, `go test`, and the Windows build, so the
public repository and every release are reproducible without private files.

## Applying a recipe

The installer verifies the original disc image, reads each resource from the
backup, and dispatches on its format:

- `tile_atlas_8bpp`: decode the map and tiles into a pixel plane, apply every
  erase region, blit the label masks, then repack the whole atlas. One tile is
  claimed per distinct 8x8 cell image; the repack fails if the atlas needs more
  tiles than it has.
- `mono_bitmap_1bpp`: copy the plan's packed slot bytes into the original
  resource at their declared offsets. A `wrap` canvas draws a paragraph into a
  288x64 bitmap, choosing the largest size that fits the width and line count.
  Descriptions use this with a 16px line pitch and at most four lines.
- `story_page_2bpp`: replace the page's 196x48, 2bpp image and rescale its
  voice timing table to the translated character count. The page tail, which
  holds voice data, is preserved byte for byte. Unifont 16px is tried first;
  pages that do not fit fall back to the language font at 14px down to 9px.
- `card_tilemap_8bpp`: render one of the seven opening character cards into an
  indexed 8-bit tilemap. The recipe stores the map/graphics offsets, the palette
  indices used by the art and the translated layout; the compiler deduplicates
  8x8 tiles and emits only the map and graphics regions. The original header,
  palette and unused tail stay untouched.
- `word_patches_16be`: replace big-endian u16 words in a script resource. Each
  patch declares its offset, the pristine value and the new value; the
  installer refuses a resource whose current word is not the declared original
  and leaves every other byte alone. Resource `0117` uses this to move the
  cook's five restaurant lines from speaker index 14, which the shell draws
  from a baked Japanese sprite, to index 30, which draws 02CB slot 29 with the
  translated name (厨师 / 요리사 / Cook).
- `plate_bitmap_8bpp`: replace one pre-rendered 72x48, 8bpp speaker nameplate.
  The shell blits the canvas at RAM `0x2EB080` without clipping and never
  redraws it as text, so the recipe owns every pixel. `canvas` fixes the size,
  offset and the three legal palette indices (0 transparent, 1 shadow, 77
  body); `bands` are the original line rows, and each line is centred on its
  band with the largest font size that fits both the band and the canvas. The
  640-byte tail past the canvas stays as shipped.
- `binary_patches`: copy the original executable, require each patch's original
  bytes at its offset, replace them, and verify the declared patched size and
  SHA-256. The sequel patch changes one two-byte branch so the frontend uses the
  translated texture.
- `texture_atlas_rgba`: decrypt `Texture.tex`, decode the PNG atlas, verify its
  dimensions, part count and every declared part box against the original, then
  replace the changed label and panel regions. The container header, `Parts`
  metadata and trailing data are preserved; only the PNG size and section end
  are updated.

For `Texture.tex`, each label layer is transparent except for opaque white text
and clears its whole part box first, matching the release behaviour. The seven
option panels reuse the original background: the title band is rebuilt from one
text-free row, the body is cleared to black, and the translated title and button
are composited over them. The Go installer reproduces Pillow's alpha
compositing arithmetic exactly, so the generated atlas matches the reference
renderer pixel for pixel.

The generated resource must match its expected hash and length. The installer
computes the final image hash from the bytes it actually wrote, and reports the
texture's generated hash and size through the same dynamic identity path; the
install record stores them, so `status`, `verify` and `restore` keep working.
Changing languages regenerates the texture and all resources from the original
backup rather than layering one language over another.

## Phase scope

Generated disc resources (3046: 389 UI resources and 2657 story pages):

| Group | Resources |
| --- | --- |
| Opening character cards | `00E2`, `00E4`, `00EA`, `00EC`, `00EF`, `00F0`, `0101` |
| Restaurant script | `0117` |
| Mission banners | `02B9`–`02C8` |
| Shared UI atlas | `02C9` |
| 1bpp text bank | `02CB` |
| Description bitmaps | `02CC`–`0409` |
| Chapter cards | `040D`–`041E` |
| Save-scene titles | `041F` |
| Job prompt | `0439` |
| Save/load screen | `043F` |
| Title panels | `0444`, `0445` |
| Speaker nameplates | `1044`–`105C` (22 used plates) |
| Story pages | `P1001`–`P17220` (2657 nonblank pages) |

The 318 description bitmaps are item, special-command, skill/magic and
class/monster descriptions. Each is a 288x64 1bpp canvas with wrapped text.

The 2660 story slots are 4096-byte, two-sector pages. Each holds a 196x48 2bpp
image (2352 bytes), reserved bytes, and a u16 character count plus a
`count + 1` entry timing table. Three slots are blank in every language and stay
untouched. The remaining pages are re-rendered from the story translations and
the original timing curve is rescaled to the new character count; the tail after
offset 2528 is preserved. Unifont wraps each paragraph into balanced lines and
keeps closing punctuation off the start of a line.

## 1bpp polarity

The 1bpp text resources (`02CB`, `02CC`–`0409`, `040D`–`041E`, `041F`, `0439`)
use bit 1 for the transparent background and bit 0 for the white glyph, so a
text bitmap is mostly ones. A `mono_bitmap_1bpp` write must therefore use
`"background": 1, "ink": 0`. Swapping the two renders the glyphs as holes in a
solid block: chapter cards paint an opaque white rectangle over the town art
and the letters show the artwork through them. The private E2E compares each
generated 1bpp resource's ones fraction against the pristine resource and fails
on an inversion.

Chapter cards (`040D`–`041E`) also match the original layout: the day line is
left aligned at x=10 in a y=2..24 band, and the title line is centered in a
y=33..55 band. Both bands use `max_size: 22`, the size that fills the original
22-pixel line height. Canvas writes accept per-line `align` and `left`; a line
without them inherits the write-level values.

## Speaker nameplates

Twenty-two speaker plates cover 124 dialogue lines across twelve script banks.
Opcode 61 loads one of the resources `1044`–`105C` into a 72x48 8bpp staging
buffer at RAM `0x2EB080`, and opcode 4/5 with variant 42 blits that buffer. The
same speaker index therefore shows コック in some scenes and 厨师 in others: the
restaurant script's five lines use index 14 (baked art) while the 02CB slot 29
path draws text. `0117` now repoints all five lines, and the art is translated
so every remaining site shows the localised name.

Each `plate_bitmap_8bpp` recipe fixes the 72x48 canvas at offset 0 with three
palette indices: 0 transparent, 1 drop shadow at +1,+1 and 77 body. `bands`
copies the original line rows (for example y=0..13 and y=16..29), and `left`
keeps the original x origin. The compiler wraps each name, centres every line on
its band and picks the largest size from `max_size` down to `min_size` whose ink
fits the canvas width minus one shadow pixel and does not collide with the line
above or below. Pillow antialiases the mask, so `threshold` (default 128) turns
it into the two legal ink indices before the shadow is added. The 640 zero bytes
after the canvas are not part of the write.

Eighteen further speaker sites use variants 67–71. Those take the other branch,
`0x1043 + tableIndex` loaded through the 148-entry whitelist in the boot image;
their art lives in `10B7`–`10BB`, whose encoding is still unidentified, so those
scenes keep the Japanese plate for now.

`Texture.tex` contains 502 parts. Phase 3 changes 370 of them: 363 labels plus
seven option panels. The atlas keeps its 2370x4394 dimensions and 2048-byte SSF
header. The re-encoded PNG is padded back to the original 1,374,158-byte
section so the shell's fixed `Parts` offset (1,374,200) does not move; the
container keeps its 1,392,384-byte size. Its hash and size are recorded after
generation.

The public fonts change the pixels relative to the old candidate ZIPs, so the
recipe no longer requires byte parity with those payloads. `expected/` records
the reference pixels for all three languages. The private E2E gate installs all
three languages, decodes every resource, executable and texture, compares them
with the committed references, proves that only declared sectors and regions
changed, and exercises switching, restore, determinism and rejected-plan paths.

Full E2E needs a pristine copy of the three game files (512 MiB) and only runs
where they live. `tools/recipe_checks.py` covers the part that needs no game
data, so CI runs it on every push: the plan is gated against the recipe, the
public tree is checked for stray game data, and the compiler must reject
fourteen malformed recipes. The private E2E imports that module, so each rule
lives in one place.

## Changing text

1. Edit the string or box in the matching `resources/<id>.json`, `story.json`
   or `texture.json`.
2. Compile. The compiler fails fast on a missing font, a box outside the atlas,
   a 1bpp slot that cannot fit, text that does not fit its box, or rendered
   bytes that differ from `plan.lock.json`.
3. If the edit intentionally changes pixels, rerun with `--write-plan-lock`
   after reviewing the report.
4. Run `tools/recipe_checks.py` — CI runs it too, and it needs no game files.
5. Run the private `fs2/work/tools/recipe_e2e.py` gate. `--fast` installs one
   language, checks the disc, executable and texture against the references and
   stops after restore (about 35 seconds); a full run installs all three, and
   also exercises determinism, upgrade, rejected plans and the compiler cases.
6. Update `expected/<language>.json` only when the new pixels are the intended
   result, and record the new hashes in the change description.
